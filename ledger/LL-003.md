# LL-003. A page counts as sent only when the notifier says it was delivered

**Date.** 2026-11-10.

**Decision.** `page()` in `example/service/app.py` returns True only when the notifier's result has `delivered` set to True. The test for it calls the real `page()` with a fake notifier, once delivering and once failing.

**Reasoning.** This is a correction. The baseline docstring claimed: "Return True only if the notifier delivered it." The code returned `bool(result)`. Any non-empty result is true, including `{"delivered": False}`. So a failed page was recorded as sent.

The baseline test did not catch it. It patched `page()` out and asserted on the patch, so it passed whatever `page()` did. The docstring was an unverified claim with a green test beside it.

Found by reading the notifier's return value against what `page()` checks. The new test fails on the baseline and passes on this commit.

This is modelled on a correction in the source system. There, a pager function read two keys that its router never returned, so its delivered flag was always false. The page had never run in production: its tests patched the call, and the mode that would have called it had never run. The pager was moved onto the shared alert dispatcher, and a drill command now fires the real path end to end.

**Supersedes.** None. It corrects the baseline of `example/service/app.py`, which carried no entry of its own.

**Commit.** Lands with the change to `example/service/app.py` and `example/service/tests/test_app.py`.
