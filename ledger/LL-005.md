# LL-005. The governance checker reads file names from git unquoted

**Date.** 2026-11-24.

**Decision.** Every git call in `tools/check_governance.py` passes `-c core.quotepath=off`, so git prints file names as they are. A file under a behaviour path with a non-ASCII name, such as `tools/café.py`, now counts as behavioural. A changed file with a non-ASCII name is now read for open `[ASSUMPTION — verify]` markers. Test 15 in `tools/tests/test_check_governance.py` covers both.

**Reasoning.** This is a correction. LL-004 claimed that the build fails when "a non-merge commit in the range changes a file under a behaviour path and adds no new `ledger/LL-NNN.md`", and when "a file changed in the range holds an open marker". That was true only for ASCII file names. By default git quotes a non-ASCII path in the output of `diff --name-status`, `diff --name-only` and `ls-tree`, writing `tools/café.py` as `"tools/caf\303\251.py"`. The checker read the quoted form. That form matches no behaviour path, and it names no file that `git show` can read. So both checks passed without a word.

Found by operator review of `bffd1d2`, with a probe: a commit that adds `tools/café.py` and no entry. The checker exited 0. On this commit it fails and names the file.

With `core.quotepath=off`, git still quotes a name that holds a double quote, a backslash or a control character. Such names are not handled.

**Supersedes.** None. It corrects LL-004, which stays live.

**Commit.** Lands with the change to `tools/check_governance.py`, `tools/tests/test_check_governance.py` and `ledger/DIGEST.md`.
