# LL-004. CI fails the build when the ledger, marker or digest rules are broken

**Date.** 2026-11-24.

**Decision.** CI runs `tools/check_governance.py` on every push and every pull request, after the example tests and the checker's own tests in `tools/tests/`. The build fails, with one line per broken rule, when any of these is true:

- A ledger entry at head has no title line `# LL-NNN. <title>`, has a title number that differs from its file name, or lacks one of the five fields: Date, Decision, Reasoning, Supersedes, Commit.
- `ledger/DIGEST.md` differs from the digest the script generates from the entries. It holds one line per entry: `LL-NNN | live | <title>` or `LL-NNN | superseded by LL-MMM | <title>`.
- A non-merge commit in the range changes a file under a behaviour path and adds no new `ledger/LL-NNN.md` in that same commit, and has no `Ledger-Exempt: <reason>` trailer with a reason. The behaviour paths are `example/service/` except `example/service/tests/`, `tools/` except `tools/tests/`, and `.github/workflows/`. The list lives in the script.
- A commit deletes, renames or edits an existing entry, other than to add one line `Superseded by LL-NNN on YYYY-MM-DD.` (with blank lines around it).
- A commit adds an entry whose number is not above every entry in its parent. Gaps are allowed.
- A file changed in the range holds an open `[ASSUMPTION — verify]` marker at head. The marker in inline backticks or a fenced block is a mention. In a blockquote it is open. This fails pull requests and pushes to `main`. On any other push it is printed and the build stays green.

On a pull request the range is the base branch's fetched tip to the pull request's head. On a push it is the previous tip to the new one. The fallback is the merge-base with `origin/main` when the previous tip is all zeros or not in the clone.

**Reasoning.** The pull request template asked three questions and CI backed none of them. CI installed from the lock, diffed against it and ran the example tests. The same-commit rule, the never-delete rule and the marker rule were enforced only by a reviewer's eye. A rule that a machine can check should fail the build, not wait for review.

The checker judges only the commits in the range. It does not re-judge history before it. On `main` before this entry, `38572a1` (the example service), `2f1c682` (the CI workflow) and `1c93203` (the action bump) changed behaviour paths with no entry. They stay as they are.

**Supersedes.** None.

**Commit.** Lands with `tools/check_governance.py`, `tools/tests/test_check_governance.py`, the change to `.github/workflows/ci.yml` and `ledger/DIGEST.md`.
